# ADR-0087: A Commander Event is a Variant of a Magic: The Gathering Event, produced from Feature Match Slots that seat up to four

Accepted · 2026-11-13 · [#1173](https://github.com/KeeprDigital/stream-keepr/issues/1173). Built in slices: the Variant and what a Commander Event is offered are in ([#1174](https://github.com/KeeprDigital/stream-keepr/issues/1174)), and so are a Slot's four typed Seats, their Commanders and Swap Seats ([#1175](https://github.com/KeeprDigital/stream-keepr/issues/1175)), and the Commander Session with its Feature Match Controls ([#1176](https://github.com/KeeprDigital/stream-keepr/issues/1176)), and a Seat's pasted Deck List with its Deck List Screen and the Cards page ([#1178](https://github.com/KeeprDigital/stream-keepr/issues/1178)), and the overlay's four Seats, its two Graphic Item kinds and its four-Seat templates ([#1177](https://github.com/KeeprDigital/stream-keepr/issues/1177)), and the public read ([#1179](https://github.com/KeeprDigital/stream-keepr/issues/1179)). Follows ADR-0057's shape; extends ADR-0056 and ADR-0080; leaves ADR-0058's Session-only swap to Two-Player Events.

Commander is streamed as one table: up to four players, one game, cameras on each. Nobody keeps tournament data during such a show, and the decks come from deck-building sites.

### Decision

**Commander is a Variant of a Magic: The Gathering Event, not a third Card Game.** An Event's Variant is Two-Player or Commander, chosen with its Card Game when it is created and never changed. Every Event that exists is Two-Player; a One Piece Card Game Event has none. It is stored on the Event (`events.variant`, migration `0001_event_variant`, which makes each existing Magic: The Gathering Event Two-Player), written only by the create, and left out of the update as the Card Game is.

**A Commander Event is produced from its Feature Match Slots alone.** It holds no Players, Rounds, Matches, Match Results, standings, Metagame, Archetypes or Broadcast Deck Lists. Melee Sync, Feature Match Slot Promotion, Assignment and Reverse Sync never run for it. It is offered the Background, Card Spotlight, Deck List, Feature Match Controls, Feature Match Overlay, Broadcast Graphics and Talent Screen Modes, and none of the Players, Matches, Event Structure, Sync, Metagame, Archetype Review or Integrations pages. Its Match Format settings offer no best-of, extra turns or points system. It keeps the Cards page, which picks a Slot and shows each Seat's Commanders and list, a card chosen there previewing on Card Spotlight, as on a One Piece Card Game Event (ADR-0057).

**A Commander Slot has four Seats, each typed.** A Seat holds a name, pronouns and LGS where the Event shows them, one or two Commanders picked by card search, and an optional Feature Match Deck List. Seats are places at the table, numbered clockwise, and operator surfaces show each where it sits. An empty Seat is not in the game: the turn passes over it and nothing renders for it. No number of Seats must be filled; one filled during a Session joins at starting life, and one emptied leaves at once. Swapping two Seats exchanges their players in the Slot itself, with their typed data, Commanders, Deck List and live state, and holds after the Session: a Commander Slot has no pairing order for a Session to keep apart (ADR-0058). Swap Seats is the Slot's own write (`POST …/feature-match-slots/:slotId/swap-seats`), one statement exchanging the two Seats, refused on any other Event.

**A Commander is held on its Seat as one printing.** The operator's card search answers it, and the Seat keeps its Scryfall id, its name (the front face's, for a card with two), colour identity, set code and collector number; its image is the printing's. The card search offers paper cards, and a held Commander's other printings are found by the card's oracle id. A typed Seat keeps a name, pronouns, LGS and its Commanders, and nothing else a create or a setup save sends, and a write linking a Commander Event's Slot to a Player or a Match is refused: it has no record, and its deck name and colours are written by the save from its Commanders, names joined by " / " and colour identity together, so everything that reads a Seat's deck reads a Commander deck unchanged.

**Seats widen the two-sided scheme; nothing is rewritten to a list of Seats.** `player3` and `player4` join `player1` and `player2` in the Slot's columns, the Session state, the Source Roles and the tokens. Every Two-Player shape stays as it is, and Commander logic branches on the Variant. In the Slot, Seats 3 and 4 are typed data alone (`player3_data`, `player4_data`, migration `0002_feature_match_slot_seats`), with no `player3_id` or `player4_id`, because no Seat of a Commander Event links a Player. `Seat` names all four; `PlayerSide` stays the pair, and is what a Two-Player contract (an overlay setting) validates against until the slice that widens that contract; a Deck Source's Seat is any of the four. A Session command names a `Seat`, and the Session it is sent to decides: one naming Seat 3 or 4, or a Commander Session's own command, is refused (400) by any other Session, and a Commander Session refuses a game win, extra turns, a Sideboard reveal and Swap Players the same way. An empty Seat 3 or 4 is left out of the Slot response and its realtime message, so a Slot of any other Event reads byte for byte as it did, and a setup save naming Seat 3 or 4, or a Commander, on any other Event is refused.

**A Commander Session plays one game.** It tracks each Seat's life (40 by default), Commander Damage, counters and cards kept, which Seats are Eliminated, and the turn, which passes in Seat order from whichever Seat goes first, its number going up each time it returns to that Seat, as a Two-Player turn's does. Commander Damage is counted per opposing Commander, a pair separately, and entering it lowers life by the same amount. Only an operator sets Eliminated. The Session completes when its operator declares a winning Seat or a draw, and nothing outside it records the outcome. It has no best-of, game wins, extra turns or Sideboard reveal, and its clock is untimed unless the Event's Match Format sets a countdown. Commander tax, the monarch and the initiative are not tracked.

A Commander Session's snapshot carries the Variant and all four Seats, empty or not, and its state a `player3` and `player4` beside the pair; every other Session's snapshot and state hold neither, so they read as they did. The reducer branches on the snapshot's Variant. A Seat is in the game while it is filled: a command naming an empty Seat changes nothing. Commander Damage is held on the Seat that took it, an entry per opposing Seat and Commander number (first or second), and a count cannot go below none, so taking back more than was entered raises life only by what was there. The turn's number goes up when the turn reaches or passes the Seat that went first, so a round is still counted once that Seat is Eliminated or empty; stepping back undoes it and stops at the first turn. The outcome is state of its own (`outcome`, a winning Seat or a draw) which sets the Session complete; taking it back reopens the game. A reset of either kind starts a new game from the snapshot, its clock included: the game is the whole Session.

A setup save corrects the Session as it does any other, and the correction is where a Seat joins or leaves: one filled since joins at starting life, and one emptied has its state cleared, the turn it held passed to the next Seat, and the Commander Damage counted against its Commanders dropped, as is that of a Commander a Seat no longer holds. Life already lost stays lost. Where nobody is left to take the turn an emptied Seat held, the game waits on a Seat to go first again. Swap Seats is one Session event (`SwapSeats`, server-only, as `SnapshotCorrected` is), carrying the Slot as it now stands: it exchanges the two Seats' state and renames each in the turn, the Seat that went first, the winner and the Commander Damage their Commanders dealt, so no reader sees a player beside another's life. It is never refused for a Session that moved on, because the Slot has already swapped.

Feature Match Controls show a Commander Slot's Seats as a two-by-two table, clockwise from the top left, on the Feature Match page and the Feature Match Controls Screen Mode alike: each Seat's life, a Commander Damage stepper per opposing Commander, counters, cards kept while mulligans are taken, an Eliminated toggle and a control declaring it the winner, around the turn and a control declaring a draw. A Screen Output reads its Event's Variant to choose that layout. The Screen's left side, its Match orientation and its record do not apply. Its life permission covers Commander Damage and the Eliminated toggle, and its game win permission covers declaring the outcome and taking it back, so a Screen allowed neither changes no game. The Edit Match State dialog, Change First Player and Match reset are not offered. Commander Damage entered beside a life typed in the same moment is sent ahead of it, so the Seat is left at the life its operator saw. What an Event tracks of Feature Match state is read by its kind: a Commander Event tracks no overtime and no Sideboard.

**A Commander deck is its Commanders, with or without a list.** A Seat's deck and colours are its Commanders' names and colour identity. A pasted list goes through the Magic deck text parser Broadcast Deck Lists use and holds each card as the exact printing its line names: a set and collector number name one printing, a set alone one from that set, and neither the card's default. A name printed on a printing in place of the card's own, a flavor or printed name, names that printing as the card it is, set or no set: Scryfall's collection lookup matches no such name, so the names it misses are searched for together, twenty to a search of at most five pages ([#1201](https://github.com/KeeprDigital/stream-keepr/issues/1201)). It is built for Moxfield's own copy, the only one of Moxfield's four that carries printings: its first card is offered as the Commander, and the operator confirms it, changes it or adds a second before the list is saved. Moxfield's Arena, MTGO and plain-text copies read too, without printings: a `Commander` heading names the Commanders where there is one, `About` and `Name` lines are ignored, and the cards trailing the list after a blank line, past the Sideboard where there is one, are offered as the Commanders. A Sideboard section is dropped and the preview counts what went; `*F*` and `*E*` foil markers are dropped on every Magic paste. A list naming no Commander or more than two, an unresolved card, or a printing that cannot be found is refused, naming the line at fault. Nothing checks legality, colour identity, singleton or card count. A paste replaces Commanders picked by search, and while a list is held its Commanders are picked from its cards. A Deck List Screen names a Seat as its Deck Source and shows the Commanders apart, ahead of the Mainboard, or the Commanders alone when the Seat holds no list.

A Seat's list is a Feature Match Deck List held on the Seat by reference, as a One Piece Seat's is (ADR-0057), so it moves with its player on Swap Seats and a setup save keeps, drops or releases it by the same rules; the write that creates a Slot takes none. Its cards are rows of their own (`feature_match_deck_list_mtg_entries`, migration `0003_feature_match_deck_list_mtg_entries`), each the printing as Scryfall answered it. The list holds every card kept, and the Seat names which are its Commanders: the Mainboard is every copy but one of each, and a setup save that changes the Commanders counts it again. A setup save leaving a Seat's list beside no Commander, or beside one that is not a card of the list, is refused (`409`), so a form opened before a paste cannot put its searched pick back. The paste is previewed and saved at `…/feature-match-slots/:slotId/commander-deck-lists`. A save names the Commanders confirmed, each a printing of the list, and is the Slot setup write's, so it corrects the Seat's Session and announces the Slot; a refused one answers `422` with the lines at fault (`COMMANDER_DECK_LIST_INVALID`). The parser offers the Commanders by one rule for all four copies: the cards under a `Commander` heading, else those trailing the Sideboard after a blank line, else, in a list with no heading, the one or two cards after its last blank line, else the first card. A third card so offered, a `Commander` heading with none, and a `Companion`, `Maybeboard` or card-type heading refuse the paste. A Sideboard's lines are counted and never resolved, and one the line rules cannot read is dropped with the rest. A paste of a list that still holds the Seat's Commanders previews them as confirmed, in place of the offer.

A Deck Source's Seat is any of the four, and a Screen write naming Seat 3 or 4 on any other Event is refused (`400`). A Commander Event has no Player and no Broadcast Deck List to show, so its Deck Source picker offers a Slot and a Seat alone, and a Screen entering Deck List mode with no source chosen starts on the Event's first Slot, Seat 1, as a One Piece Card Game Event's does (ADR-0057). The Screen follows the Seat as a One Piece Seat is followed: whoever sits there now, and the list their Seat names by id, read through the Screen (`…/commander-deck-lists/:deckListId`), so Swap Seats, a re-paste or a change of Commander reaches it with the Slot. It draws in the Magic layout, each card the printing saved, with the Commanders where a Sideboard would sit, ahead of the Mainboard and placed and laid out as a Sideboard's cards are. Its settings offer no Board Selection, Sideboard or companion. A Seat nobody sits in shows nothing. The Cards page's Feature Match Deck List mode picks a Slot, there being no Round or Match, and shows each Seat somebody sits in, its Commanders apart from its Mainboard; it has no Player Deck List mode, and a card chosen previews on Card Spotlight as any Magic card does.

**The overlay gains terms, and a template's content decides which Events are offered it.** Source Roles `player3` and `player4`; each Seat's tokens, without a record; `player{N}Commander1Image` and `player{N}Commander2Image`, rendered as a Leader's image is; the same fields in the Broadcast Graphics binding catalogue. The Player Life Graphic Item reads any Seat. A Commander Damage Graphic Item shows what one Seat has taken, and a Seat Indicator Graphic Item, offered on every Variant, is shown while its Seat is the active player's or Eliminated. Counters, the turn number and cards kept stay off air. A Feature Match Layout Template naming Seat 3 or 4, or a Commander term, is a four-Seat template offered to Commander Events alone, and every other template to every other Event; one four-Seat built-in ships (ADR-0080). The Feature Match Sample and Stress Datasets and the Theme preview gain a Commander set, which a Theme preview offers as a pick beside the Card Games. The public read (ADR-0056) adds Seats 3 and 4, their life and each Seat's Eliminated state, and no game-win fields; an empty Seat's fields are there and blank.

An Event's kind decides the tokens it is offered and holds values for: a Commander Event four Seats' with no record or Leader image, every other Event the pair's with no Commander term, so a Two-Player Event's public read is unchanged. A Graphic Item reads the Seat its kind is set to, the Seats its text's tokens belong to, or the Seats its group's children read, and renders nothing while every one of them is empty; a Source Item whose Source Role is an empty Seat renders nothing either. Only a Commander Slot has empty Seats in this sense: a pair's items and sources render unseated, as they did. A Commander's image is loaded on air from Scryfall alone. In the binding catalogue a field or relationship naming the Commander Variant is offered to Commander Events alone.

A Commander Damage Graphic Item paints as text does: each count beside the card of the Commander that dealt it, a count at zero left out, and nothing at all, surface included, while it has none to show. Only a host supplying a Commander game's context is offered it. A Seat Indicator Graphic Item paints one Shape Geometry surface while its Seat has the turn or is Eliminated, whichever its author picked, and plays its enter and exit on the flip through the per-item phase trigger a Sideboard reveal uses (ADR-0015), timed on each output's own clock. It marks the active player on any Event that tracks one.

A layout is four-Seat when a Source Item, a Graphic Item or a token in it names a third or fourth Seat, or when it holds a Commander's image token, a Commander Damage Graphic Item or a Seat Indicator set to Eliminated. The library marks such a template, lists it to Commander Events alone and every other template to every other Event, and placing one on an Event it is not offered to is refused (`409`). Any other Screen write, a create, an update or a mode configuration write, giving a Screen of any Event but a Commander Event a four-Seat layout is refused too (`422`, `FOUR_SEAT_LAYOUT_COMMANDER_ONLY`). A Commander Event's Screen may still hold a pair's layout, so this is wider than what is offered, and only a layout the write changes is asked, so a Screen already holding one keeps saving. Saving to the library is asked nothing, as a template belongs to no Event ([#1201](https://github.com/KeeprDigital/stream-keepr/issues/1201)). The four-Seat built-in is Commander Table (`builtin:commander-table`): Seats two by two, clockwise from the top left as Feature Match Controls show them. A Theme preview picks Commander beside the Card Games and shows that built-in against the Commander sample. A Screen's "Reset mode settings" writes a layout its Event is offered: Commander Table on a Commander Event, and the default layout on every other Event ([#1201](https://github.com/KeeprDigital/stream-keepr/issues/1201)); until the Event has loaded, the reset is held and says so. A layout saved on an Event it is not offered to is saved, and the library says at once that this Event does not list it and why; a saved entry is marked four-Seat as a listed one is. A picker labels a Commander Slot by every Seat somebody sits in, in Seat order, passing over an empty one, and lists under it the deck of every Seat that holds one.

### Why

A Commander Event uses Magic's cards, card data and deck text, so a third Card Game would fork every Magic card path and give some sixty Card Game branches a third answer for no difference. What does differ, how many sit down and how a game is won, is what a Variant names.

Slots alone match how such a show is produced, as ADR-0057 found for One Piece: one table on camera and no source of results. Players, a Metagame and Archetypes would be data nobody enters.

The two-sided names are public contracts: the vMix read, the overlay tokens, the binding catalogue, saved layouts and Template Packages, across some 1,400 source and 2,000 test occurrences. Widening them leaves every Two-Player Event, layout and package byte-identical; a Seat list would rewrite all of it for no change an operator sees.

Moxfield's Arena copy has the `Commander` heading but drops every card Arena lacks and carries no printings, so the labelled format is the wrong one to build for; its own copy keeps both and marks the Commander only by putting it first, which is why the operator confirms it.

There is no general way for a layout to show something by live state, and each such behaviour is built into an item kind, as the Sideboard reveal is. Two more kinds follow that; a general condition is a larger decision this one does not need.

### Consequences

- Every player is typed, and their deck pasted, each time they are featured. Nothing carries from one Event to the next.
- Commander Damage is keyed by Seat and Commander number, not by card, as the overlay's `Commander1` and `Commander2` terms are: replacing a Seat's first Commander keeps its count, and removing the first of a pair leaves its count on the one that takes its place and drops the second's.
- A Session opened on a Commander Slot before its Session had four Seats is Two-Player in shape until its next setup save or Swap Seats, which gives it the missing Seats, or a new Session.
- A Commander game's first Seat is chosen once: changing it means a reset. Its Controls have no dialog for correcting the turn number or the Seat whose turn it is beyond stepping.
- `player3` and `player4` exist in shared types on Events that never use them, and every Two-Player path must ignore them. Code naming a side or `PlayerSide` means one of the two Seats every Slot has; `Seat` is any of the four.
- A Commander's name and colour identity are what the operator's browser read from the card search, checked for shape and not against the card: a wrong one mislabels a deck on air and nothing else.
- What was declared Magic: The Gathering only is declared `TWO_PLAYER_MAGIC_ONLY`. Every page and Screen Mode declares the kinds of Event it is `offeredTo`, where it declared `cardGames`: an `EventKind` is an Event's Card Game with Magic: The Gathering split by Variant, a key for declarations and config and not a term of the domain. No kind shares a Card Game's key, so a Card Game cannot be passed where the Variant must be read too.
- A Screen write that would put a Screen into a mode its Event is not offered is refused (`SCREEN_MODE_NOT_OFFERED`), for every Event: before this only the pickers kept a Standings Screen off a One Piece Card Game Event. It is asked only when the mode changes, so a Screen already stored in such a mode keeps saving.
- Five players, one-on-one Commander, or a Commander tournament with standings would each reopen this decision.
- An installation older than this refuses a four-Seat Template Package by the identity of its terms, as it refuses any unimplemented one.
- A Broadcast Deck List write, and enabling them on the Event, is refused for every Event but a Two-Player Magic: The Gathering one (`holdsBroadcastDeckLists`).
- `0001_event_variant` backfills, though ADR-0083 has production's database wiped before the next release: local and preview databases hold Events, and README § Database asks a held-back test of any migration that alters a populated table.
- The Magic deck text parser serves two owners, a Broadcast Deck List and a Seat, with one set of line rules.
- A Moxfield paste asks for about a hundred exact printings. The resolver asks Scryfall's collection endpoint for them 75 to a request, for a Broadcast Deck List as for a Seat; a printing the answer lacks is one that cannot be found.
- A hundred-card list is about a hundred card images, which a Deck List Screen loads before it shows the deck (ADR-0053): a Seat's first show takes as long as they take to arrive.
- A Commander's place in a pasted list is a convention of the site that exported it. A real export of a partner pair ([#1201](https://github.com/KeeprDigital/stream-keepr/issues/1201)) puts both first in Moxfield's own copy, so only the first is offered and the operator adds the second; under the `Commander` heading in the Arena copy; and, the deck having no Sideboard, after the list's last blank line with no Sideboard heading in the MTGO and plain-text copies. The operator's confirmation is what makes each safe.

### Rejected alternatives

- **A third Card Game.** Forks every Magic card, search and deck path, and every Card Game branch.
- **A list of Seats everywhere.** The cleaner model, at the cost of every Two-Player contract and test, for nothing on air.
- **Players and a Metagame, as One Piece has (ADR-0074).** Nobody would enter them for a single table.
- **Pods from Melee Sync.** Its mapper refuses more than two competitors, and these shows are not run from Melee.
- **Deriving Eliminated** from life, Commander Damage or poison. Replacement effects and concessions make the operator the only reliable source.
- **A general state-driven visibility for layouts.** Wanted eventually, but not needed for two indicators.
